VUE · ELEMENT PLUS · SHADCN-VUE REGISTRY

组件源码能放进 JSON？
Registry 一定要托管吗？

可以。发布时，每一个 Registry Item JSON 可以带着一个或多个 Vue 文件的完整源码字符串；其他项目需要它时才下载。Registry 需要一个可访问的位置，但不必有专门的后端服务。

01 · 构建与分发

不是把整个组件库打成一个 JSON

组件源码仓库UserTable.vue
registry.json
→
构建脚本读取文件、填充元数据
→
按组件分开发布user-table.json
user-card.json

registry.json 是源目录：描述组件和文件路径；构建后的 /r/user-table.json 是分发包：包含 files[].content 中的源码文本。它们不是同一个文件。

02 · JSON 具体长这样

源码只是一段字符串

{
 "name": "user-card",
 "type": "registry:component",
 "dependencies": ["element-plus"],
 "files": [{
   "path": "UserCard.vue",
   "type": "registry:component",
   "content": "<template>\n  <el-card>Hello</el-card>\n</template>"
 }]
}

这只是结构示意。真正 JSON 中的换行和引号会转义；CLI 读取后，将字符串写回到 Vue 文件。

03 · 多大？

按需下载，而非一次拉全部

一个简单的 Vue 文件通常只有几 KB；复杂模板可能几十或几百 KB。每个组件独立 JSON，下载特定条目即可。

在本次 Demo 的本地构建产物中，5 个条目加索引共约 13.38 KB（未压缩），只是示例规模，不代表大型组件库。

Element Plus 本身通常作为 npm 依赖安装，不会把整个 Element Plus 的源码复制进每个 Registry Item。
04 · 托管

静态网站托管就够了

在哪里怎么获取适合什么
本地文件或 dev server本地路径、localhost开发与实验
GitHub Pages / Cloudflare Pages公开的 HTTPS JSON 地址公开或团队通用组件
私有 HTTP API / 对象存储鉴权的 JSON 地址私有组件与权限控制

托管 Registry ≠ 托管 MCP Server。前者是静态数据；后者需要一个能接受 MCP 协议请求的服务进程（可以由用户电脑运行官方 MCP）。

05 · 如何工作

另一个 Vue 项目怎样获取组件？

用户要求“安装 UserTable”
→
CLI 或 MCP读取远程 Registry Item
→
当前 Vue 项目写入 .vue 文件、处理依赖
GET https://example.com/r/user-table.json
→ 读取元数据、files[].content、依赖
→ CLI 安装 Vue 文件至当前项目
→ npm 安装 element-plus（若项目尚未安装）
你的质疑成立：如果 Claude Code 或 Codex 已在组件源码仓库里，直接 grep / 读取 .vue 往往更简单。Registry 的主要增量是跨项目分发、依赖描述和统一安装入口；MCP 是 Agent 使用它的一种接口，而非必需条件。

设计师怎么理解？

组件源码仓库是厨房；Registry 是菜单和每道菜的打包配方；静态托管是公开菜单的地址；CLI负责取件和安装；MCP给 Agent 一个标准化的点单接口。
